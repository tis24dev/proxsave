# ProxSave 0.35.0 Screen 0 Entry Design

## Context

The first release on the next line will be `0.35.0-beta1`. Screen 0 finalizes
prerelease versions before lookup, so the registry entry must use the final key
`0.35.0` and must exist before the beta tag is created.

The release contains three user-visible changes since `0.34.0`: PVE cluster
database snapshots can invoke `sqlite3` again, trusted personal scripts may run
below user-owned homes with an explicit warning, and daemon diagnostics now
report the personal-script state loaded at startup alongside the current
configuration.

## Decision

Append one `Note` after the existing `0.34.0` entry in
`internal/whatsnew/registry.go`:

- Version: `0.35.0`
- Highlight: `PVE cluster database snapshots no longer fail before sqlite3 can run`
- Highlight: `Personal pre- and post-backup scripts can run below user-owned homes with an administrator trust warning`
- Highlight (116 characters):
  `Daemon status compares loaded and current personal scripts, with paths, ownership, modes, refusal reasons, and drift`
- Actions: omitted because none of these fixes requires a mandatory user step

The three-bullet form keeps each concern distinct without splitting diagnostic
details into several lines. Existing entries, including `0.33.0`, remain
unchanged because the registry is append-only and every release keeps its own
historical copy.

## Behavior

`LookupNotes` will map `0.35.0-beta1` to the `0.35.0` entry through its existing
version-finalization behavior. Screen 0 will therefore show the new copy to beta
users and record the `0.35.0` line as seen.

No renderer, lookup, gate, or dashboard behavior changes are required.

## Verification

- Run the `internal/whatsnew` unit tests.
- Run the release gate with `WHATSNEW_REQUIRE_VERSION=0.35.0-beta1`.
- Run `git diff --check` and the repository's broader Go test suite.
- Use GitNexus change detection before committing the registry change.
